**最新结论：本轮列出的 P1/P2 已修正或完成证据闭环，见文末“最终闭环复查”。** 前面的初始评分保留为修改前基线；不要继续把已修复的暂停剧透、会话混合、旧手机壳、假电话页签及图标拉伸列为当前已知问题。人物、握持、物品图和环境写实度仍为 1，未达到最终美术完成。

## 范围与结论

本文件主体为初始只读产品审查；收到主 Agent 后续授权后，另实施了菜单/暂停/通知/相机的局部改进，见文末实施记录。依据 AGENTS.md、v2 规格第 0/5/6/8.3 节、DEVELOPMENT.md 当前状态及相关 UI 源码。截图均实际通过 `view_image` 查看。主 Agent 正在同步修改人物、相机、门和 NPC，主体评分描述修改前快照，不能代替修改后的运行验收。

当前 UI 有可用的交互基础，也已经摆脱帆布背包与旧式手机 App 方向；整体仍更接近功能原型。主要问题是信息层级相似、开发说明出现在世界内设备、若干可点击外观缺少真实行为，以及部分图像缩放/近景资产削弱真实感。阈限感应由普通生活界面在失联后仍然照常工作产生，不应添加故障乱码、VHS、脏屏或全局泛黄。

必须保持：2026 年现代手机；2000—2010 年代建筑；简体中文；默认无 VHS；1080p60 优先；背包无帆布；左侧装备竖栏默认显示，选物换详情；物品图标保持比例；相机可移动、观察并拍照；不牺牲可读性和操作目标尺寸。

## 第一批：直接修复的高优先问题

1. **序章暂停剧透。** `ui/shell/prologue_shell.gd` 未覆盖 `_build_pause()`，继承 `foundation_ui.gd` 的 `SHELL_TITLE`，翻译为“后室”。序章暂停标题改为“暂停”，不要提前出现游戏世界名。主菜单仍保留普通房间和日期。
2. **移除设备内开发说明。** `PHONE_CLOCK_STORY_TIME` 显示“不读取设备时钟”；登记 `PHONE_REGISTER_NOTE` 说明“本地角色资料”；浏览器 `local.home` 暴露实现。替换为真实设备语气，例如“日期与时间”、普通账号资料说明、虚构网站地址。不要用文案声称尚未实现的网络能力。
3. **背包图标等比。** `field_inventory_grid.gd::_draw_rotated_icon()` 用 `draw_texture_rect` 直接填满占格矩形。应先按纹理原始尺寸做 contain，再围绕中心旋转；奇数旋转先在未旋转坐标计算容纳尺寸。占格轮廓与图片边缘分离，保持异形布局真实。使用正方图、长条图、2×1/1×2、4×3、L 形以及四向旋转复核；不修改物品占格模型。
4. **电话与闹钟取消假交互。** `_show_phone()` 的“最近/联系人”按钮没有信号连接；`_show_clock()` 的 CheckButton 仅初始 true，没有持久状态。电话页签应切真实已存在列表；闹钟若当前没有对应状态，先呈现明确只读闹钟行，不能让点击产生保存成功错觉。若新增闹钟状态，交由主 Agent 处理系统边界。
5. **相机移动与反馈。** 用户已要求边移动边拍；旧开发记录明确 camera 暂停移动，应以本轮授权替代。相机成功提示不能永久覆盖操作提示：短暂“已保存”后恢复 Esc/P 与快门帮助。保存照片应无 HUD/手机/手部，且与取景构图一致。不要把移动修复只写成文案。

## 具体视觉方案

### 主菜单、暂停与设置

保留真实静止房间作为首屏，左下日期作为轻标题；主操作为“继续”“新的一天”“设置”。难度进入二级选择，显示三种现有模式及一行准确规则说明，选择后才开局。不得改变难度或存档规则。避免三根宽黑按钮直接把日常清晨变成关卡选择器。

暂停使用与主菜单同一左对齐列，约 320–380 逻辑像素，主动作清楚，次动作间隔稍大。弱遮罩只为文字对比，不盖住整个房间。设置复用现有沉浸 UI、镜头晃动状态，使用行标题、短说明、右侧开关。不要为了视觉完整添加无功能的音量、画质滑杆。入口从主菜单和暂停都可到达，返回回到原页面。

去掉按钮层层描边，普通行透明，hover/focus 提供细左线或浅底，选中与键盘焦点仍明显。可点击行保留至少 40–44 逻辑像素。中文常规字重、22–28 标题、14–16 正文为起点，低分辨率以实际渲染为准。不可用项保留可读禁用原因。

### 手机公共外壳与主页

最新原生图已经有清楚图标、常规中文和现代浅色体系，应沿用。将主页从“白色 App 页面”变为设备桌面：主页隐藏重复“主屏幕”标题，时钟/日期自然置顶，下方 4 列图标，保留已有 App。使用干净低饱和壁纸/纯色背景即可，不必新增大幅美术资产。退出手机作为屏幕外键位提示或清晰小关闭入口，系统导航统一。

App 顶部只显示应用/当前页标题和返回；不重复全局主页标题。导航区域保留足够命中尺寸，视觉上去掉厚白色药丸按钮。状态栏“本地服务”改成可信连接状态；失联使用“无服务”，保持同一屏幕、同一电量和日常配色。关闭手机的 Esc/P 操作仍要明显可发现。

实体手机图中厚边框、巨大圆 Home 键、块状手指比 App 本身更影响 2026 设备可信度。这属于主 Agent 近景资产工作：优先改善尺度、轮廓和握持遮挡，不能靠压暗手机画面掩盖。

### 聊天

当前截图把林倩与阿明列表卡片、完整来信、全局输入框放同页；`PhoneState.messages` 仅 text/status/sequence，没有收件人。第一步应明确“会话列表→单会话”，列表仅头像、姓名、最后一句和时间；详情顶部显示联系人，正文左右气泡，固定底部输入。输入栏平时一至两行，可扩展；发送按钮置右，字数只在接近上限时突出，保留 1000 字约束和 Unicode。

**系统边界**：完整多联系人发送需要规范收件人字段及旧档迁移，由主 Agent 设计；不能在 UI 中假分配旧消息。可暂把现有消息放在明确的单一对话，其他聊天只读，但需要主 Agent 依据已授权范围确认取舍。此处不是已证实“消息发给第一个联系人”，准确缺陷是收件人不存在且表现含混。

发送失败呈现在对应气泡下，保留已输入消息和旧聊天，不能弹夸张恐怖框。聊天搜索若不支持，应删除输入框外观或实现对现有会话的本地过滤，不能继续保留可输入暗示但 editable=false 的空壳。

### 地图

用页面主要面积呈现缓存城市地图，路线卡固定在下方；街区、道路与路线采用归一化坐标随内容宽度缩放，避免固定 320 坐标在宽视口只占一角。标注住宅/便利店/办公室中少量已存在地点，保证地图与清晨语境相符。

后室中沿用同一缓存地图，定位点停止/隐藏并显示“无法获取当前位置”；不能继续用蓝点暗示可靠定位。当前 `_show_maps()` 不分 offline，只有状态栏变化，需增页内状态。搜索只做现有地点的本地查找即可，不接真实服务。新增缩放按钮必须真的缩放，否则不展示。

### 浏览器

主页以地址栏、最近访问条目为骨架，文章页用网站标题/小日期/正文段落，天气页把已有温度与天气信息建立层级，工作页正常办公语气。不要所有页面都变成一张同尺寸卡片。

现有地址框只读且无刷新。按规格允许缓存页面浏览、新请求失败；至少增加真实刷新动作，前厅加载同一静态内容，后室明确“无法连接，正在显示已保存页面”。不需要真实互联网或整套搜索引擎。所有错误是普通网络错误，不加入异常回复。

### 电话

“最近”“联系人”两个可切页签，各页紧凑列表。联系人条目采用姓名为主、号码为次，点击后显示对应联系人的拨号状态，再普通失败返回。前厅与无服务状态应自然区分，不能所有点击只给无对象的通用提示。号码无需绑定现实运营商/地域。没有实际拨号盘功能时不添加装饰拨号盘。

### 相机与相册

相机现有全屏取景方向正确；上下实黑条可以收窄为轻量局部渐变，增大世界可见面积。模式、电量、快门、返回构成最小控制组，三分线更轻，中心对焦框可短暂出现。不要添加没有实现的闪光/HDR/变焦按钮。“自动”若没有对应可变参数可作为模式文字，但不应暗示可调功能。

快门响应立即有短促反馈；实际保存完成后短状态提示，避免连续拍摄重复排队或已失败仍报成功。边移动、鼠标观察、拍摄、碰撞以及 Esc/P 返回均由运行验证确认。

相册应有明确入口、等比缩略图和单图查看；64 张上限不能变成 64 个大按钮长列表。静态源码各按钮都绑定 `_photo_texture`，需要逐照片对应的纹理或独立中性占位，不能让所有记录显示最近一张。采用按需加载/小缩略图，避免同步解码整库影响帧时间。相册满与缺文件给出普通可理解状态。

### 时钟

大号当前时间、较小完整日期、单独闹钟行即可。移除剧情时间说明；后室的 24× 变化通过数字本身被玩家发现，不加“时间异常”警报。闹钟行显示当前真实状态；不支持编辑就只读。留白可以存在，不用虚构秒表/世界时钟按钮填充。

### 公司工作台与登记

登录失效页以企业图标、标题、一段简短常见账号提示和一个实心主按钮构成；已登记页应显示真实已有姓名、员工号、状态，以普通账号页建立生活连续性。

登记页保留姓/名/生日/性别/头像，减少重复标题。说明改为账号登记语气。头像编辑按钮贴近头像；提交动作可放固定页脚，表单单独滚动，确保最小手机屏幕能发现最终动作。字段错误在对应字段附近或底部清晰出现，不能只靠顶部一闪通知。数据校验和草稿取消语义沿用现有系统。

### 背包与装备

保留用户指定左右结构。外层 94% 黑遮罩几乎切断世界，建议降为可辨背景的深灰遮罩，内容区域维持足够实底可读；不引入帆布、皮革、纸张或战术终端纹理。减少“背包与装备/装备栏/背包/背包”重复标题和多层边框，容器名、总重量、格子主体是核心。

装备为空时用低强调部位图标和“空”，装备有物时物品名与缩略图提高层级。选中使用单一细线/浅底。默认左竖栏，点击物品直接换详情，返回装备按钮保留；不把装备栏变成常驻第二大面板。

物品详情先名称与实物图，再短描述/状态/重量，最后动作。长叙事描述可滚动，操作按钮保持可达。合法/冲突不能只靠颜色，继续有轮廓和文字理由。修等比后使用真实序章电脑、钥匙、钱包截图复核；测试棕块不能作为成品视觉证据。

### 角色外观

当前宽屏合理分配预览与编辑；960 下基础选项占大半高度，脸部滑杆在底部截断，用户依赖长滚动。建议“基础/脸部/体型”三个页签切同一右栏；脸部可继续按鼻/眼/轮廓短分组，保留所有已支持参数。不要新增无实际 Morph 的滑杆。

肤色/发色应有持续选中边框或勾选，当前 swatch 仅 normal style 与 pressed 回调。提供可读名称，颜色十六进制留给工具而非主要 tooltip。滑杆需一键恢复该项默认/中值的可发现操作，预览切脸部与全身保持快捷可达。

预览像干净普通证件照/试衣观察：中性浅灰背景、柔和主光/弱补光，控制高光不冲淡脸部结构。不要以重色灯制造捏脸“高级感”。minimum_960 中波波头遮住大半脸，与面部参数观察冲突；主 Agent 应修资产/发型摆位或提供检查脸部的明确临时显示选项。原生人物是否真实需另行美术验收，UI 不能掩盖。

### HUD

保留稀疏方向。当前顶部同一通知既用于教程、拾取又用于保存，粗黑阴影使“已保存”与抵达空间争注意。建议按用途分布：教学/交互在下方中心安全区；普通拾取简短角落提示；保存小状态在角落短暂出现；错误仍清楚，不因克制而隐藏。

“去上班”保持低存在感，不加箭头/小地图。准星无交互时淡出，进入可交互距离再显现；默认沉浸 HUD 保留低值/变化状态。关闭沉浸后六属性图标与精确数值持续清楚，不能为了视觉让测试模式不可读。图标有统一笔画与等比容纳，危险状态除颜色还保留形状/文字。

通知必须避开手机、相机、角色创建与背包主操作区域；每个 UI 模态只保留当前必要提示。prologue_runtime 的重复“已拾取”截图仅证明拍照时提示可见，不能单靠静态图判定定时器永久不消失。

## 分批验收

1. **语义与基础交互**：修暂停剧透、设备开发说明、假页签/开关、图标等比、相机移动；单独验证对应动作，不重做已通过库存模型。
