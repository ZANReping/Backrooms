# Milestone 2 序章制作计划

2026-09-07。用户已明确授权制作序章，并确认以下方向；这是对此前“只做 M1”范围的后续扩展。主设计依据仍为完整 v2 规格，重点第 6 节与第 25 节 M2。

## 已确认的体验方向

- 2000—2010 年代普通城市公寓：生活痕迹可信，公共走廊空寂，城市/国家不明确。
- 手机保持真实手持道具；按 2026-09-07 最新要求，背包取消布料背景，左侧默认竖排装备槽，选物后切换详情，保留实物图像、二维异形、旋转、装备及嵌套规则。
- 1080p、RTX 4060 Laptop 上稳定 60 帧为制作目标；通过实际帧时间验证，不能只根据显卡型号承诺性能。
- 克制写实，默认无 VHS、重色差、强颗粒、夸张景深；文字和交互必须可读。

## 场景与氛围

住宅先让玩家相信自己住在这里：正确的门窗/家具尺度、踢脚线、门缝、插座、窗帘、布料折痕、常用位置的磨损和零散日用品。材质以旧白漆、偏暖木地板、灰蓝布料、磨砂塑料和薄金属为主；不统一涂成后室黄，也不把住宅做成废弃建筑。

光线来自可信灯具和窗户：早晨漫射日光、少量偏暖室内灯；公共走廊较冷的普通荧光照明。通过建筑重复结构、过渡空间、视线遮挡和疏密关系产生阈限感。门牌各不相同，不做循环走廊或空间异常预告。

序章只使用规格允许的两处轻微异常：售水点灯光嗡鸣短暂呼应 L0；普通通勤转角前环境声被吸走半秒。其他时间保持可信的城市生活环境声。无追逐、路人凭空消失、文字故障、传送门或强制异常调查。

## 制作顺序与交付内容

1. **资产与视觉基础**：筛选免费写实模型/PBR，记录许可证与哈希；制作住宅、普通走廊/街角和有限 L0 抵达空间的可运行样板，检查纹理尺度、反射和灯光。
2. **实体界面**：独立 PhoneView/PhoneController 与背包近景表现；保留核心 InventoryModel。手机具备真实主屏和六应用，Chat 自由输入、Maps 假地图、Browser 本地虚构页面、Phone 本地通讯录、Camera 实际拍摄/相册、Clock 固定剧情时间。
3. **序章主线**：闹钟→手机公司登记/角色外观→电脑包/大型笔记本/钥匙钱包→出门→可选买水→通勤意外 noclip→L0 地毯落地；第一次约 5–8 分钟，熟练可快速离开。不加迟到倒计时或失败。
4. **保存与验证**：角色注册后 checkpoint；保存 Profile、序章进度、照片引用和完整物品状态；兼容 M1 存档；验证买/不买水两条路径、读档续玩、相机、界面真实输入、连续场景切换和性能。

有限 L0 抵达空间用于序章收束与携带状态验收；不在此轮制作 M3 的无限生成/Chunk streaming，也不制作 L1–L11。

## 数据和模块边界

- `CharacterProfile`：姓名、真实生日/18–40 校验、性别和外观预设。生日按可配置固定剧情日期计算，不读取系统日期。外观驱动可见身体/手臂与头像。
- `PrologueState`：一次性教程、流程阶段、闹钟、购水与虚构余额；与库存和世界 flags 分开。
- `PrologueDirector`：序章阶段与交互门控；普通旅行与 noclip 均复用路由，核心路由内不出现 L0 判断。
- `PhoneContentCatalog`：本地静态生活内容；`PhoneState` 只保存玩家变化与相册引用。游戏不连接真实聊天、地图、电话或互联网。
- `PhotoStore`：受限的 run/photo ID 路径，图片独立于 4MiB 存档，元数据引用不可变图片；缺图不能破坏整个存档。
- `PrologueApplication`：装配序章服务与场景，M1 灰盒与原回归入口保留。通用库存、属性、保存文件服务继续各自拥有职责。
- 存档扩展采用明确版本/迁移，旧档安全默认保持灰盒状态；不把新 Profile 字段直接变成 schema 1 必需字段。

固定剧情日期/时刻、路线、商品价格均放 Resource，初始制作参数为 2026-10-18 07:48、前厅 1×、后室 24×。建筑为2000—2010年代气质，手机软件与人物生活时间线为2026。2026-09-07补充：背包取消帆布背景，改左侧竖排装备/选中详情；手机相机全屏取景；人物遵循CHARACTERS_MODELS.md。

## 资产与性能约束

- 模型优先具体作者/官方库，核实免费商用及再分发许可；已找到 Poly Haven CC0 家具模型。候选详见 PROLOGUE_ASSET_CANDIDATES.md；正式采用必须进入 THIRD_PARTY_ASSETS.md。
- 不将网站预览图当纹理；保存实际 Diffuse、OpenGL Normal、ORM。主体优先 1K/2K，只有贴近镜头的表面再增加分辨率。
- 资产查不到合适来源时，按真实尺寸制作倒角、接缝、厚度和材质完整的自有道具；不使用没有许可的搜索图片，也不以随机方块替代最终近景道具。
- 静态场景优先烘焙/受控 GI，限制实时阴影灯与反射刷新；分场景装载，避免全城同时常驻。实际材质与灯光方案以实机样板表现和帧时间决定。
- 1080p 验收记录平均/p95 帧时间、绘制调用及可用显存指标；测试与截图要标明渲染后端、分辨率及是否固定步长。固定步长功能测试不能当真实性能证据。

## 验收标准

- 正常新游戏从住宅开始；闹钟可关闭，登记数据/外观有效并自动保存。
- 手机/背包不再是调试面板风格；真实手机屏幕与背包实物近景可操作，最小窗口文字可读，沉浸模式不常驻精确统计。
- 房间内可拿放/整理必要物品；笔记本真实占用大体积/重量，无法开机；教程不强迫唯一布局。
- 六手机 App 有规格要求的有效内容；照片来自当前世界相机，消息/相册可存读。
- 买水可跳过；包内没有空间时水瓶保留为售水机旁可拾取的世界物品，整理后可取走；不能产生扣款无物品或重复生成。
- 切入像事故，携带 UID、旋转/嵌套布局、重量、液体、电量、聊天和时钟连续。
- Parser/runtime 错误清零；功能测试和代表性实机截图通过；性能不足时如实记录，不以“能运行”宣称画质完成。
